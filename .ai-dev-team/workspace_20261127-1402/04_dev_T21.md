## Blocker (needs the user's decision): shift+f3 does not reach vr-ide without the kitty protocol
GNOME Terminal (VTE) sends shift+F3 as `ESC [ 1 ; 2 R`. crossterm 0.29 (`event/sys/unix/parse.rs` line 204)
parses every CSI ending in `R` as a cursor position report, so the key is dropped before vr-ide sees it
(walk_28_shift+f3.txt: the match count stays 2/2). This is not new in T21 (shift+f3 was find.prev before),
but AC-21a requires every spec key to reach vr-ide from GNOME Terminal. Plain f3 (`ESC O R`) works.
Options: (a) find.prev = `shift+f4` (free since T21, legacy `ESC [ 1 ; 2 S`, parsed fine); (b) `f4` alone;
(c) keep shift+f3 (works only with the kitty protocol; T22 redoes find anyway).
Proposed default: (a) shift+f4. Not applied (product decision, USER-5 key choice).

## Decisions taken (for the ledger)
- ctrl+r in the editor with no file open (welcome) runs the project replace (nothing to replace in).
- Read-mode `space`/`tab` built-ins also act on the welcome screen (editor focus, no file): space space opens the palette, tab cycles.
- focus.cycle order: editor -> find bar -> side panel -> terminal (shown, with a tab) -> editor; Tab in the explorer cycles; the search panel keeps Tab for its fields; a focused terminal keeps Tab.
- Replace all in the find bar = ctrl+a in the replace field (legacy-safe; ctrl+enter is not).
- Welcome hint "Search" replaced by "ctrl+o Open file" (project search has no key).
- display_key shows built-in keys for commands without a keymap key (palette column: editor.edit_mode "space i", focus.cycle / edit.indent "tab").
