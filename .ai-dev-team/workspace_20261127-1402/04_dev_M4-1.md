## Findings for M4-2 (engine)
1. tree-sitter-highlight 0.27 gives the **last** pattern matching a node precedence (highlight.rs ~line 1107; seen: go `func greet` → `@variable` although `name: (identifier) @function` comes earlier). Layered queries are therefore joined base first. Single-file crate queries ordered first-match-wins (go confirmed; python/rust/js likely, with generic `(identifier)` rules late in the file) lose specific captures. The engine should handle precedence (e.g. reverse pattern order for first-wins queries via `Query::start_byte_for_pattern`, or its own capture walk). The go test asserts `type` instead of `function` for that reason.
2. nvim-style queries (vue, blade, twig, scss) use `@spell`/`@nospell` as second captures; `highlights_query()` strips them. They also use private `@_name` captures for predicates: a later pattern's `@_tag` on the same node also replaces the colour with none (Vue html_tags h1–h6/strong/a patterns). The custom predicate `#has-ancestor?` (blade injections) is ignored by tree-sitter, so that pattern over-matches. Capture names are nvim-style (`tag.attribute`, `variable.member`, `markup.*`; markdown uses `text.*`), so the `Capture` prefix mapping must cover them.
3. Configure the highlighter with colour capture names only (the test leaves out spell/nospell/none/conceal/`_*`).
