## Design calls
- D? (T19) "Below 60 columns" is measured on the editor column (screen minus the explorer, = the tab bar width), the width that is split; with the explorer hidden it is the screen width. 80 cols + explorer (column 60) stays right, 78 + explorer (column 59) falls back.
- D? (T19) Right panel width = round(width_percent x editor column), at least 20 columns, and the editor keeps at least 20 columns (`EDITOR_MIN_COLS`) plus a 1-column separator; the separator is the drag handle (drawn like the explorer edge: focus colour while the terminal has the keys, dim otherwise). On the right the panel's own tab bar is not a drag handle (no height to drag).
- D? (T19) Separator drag stores a percent clamped to what is drawable (`right_cols` at 10 % / 90 %), so a following ctrl+f8 / ctrl+f9 changes the drawn width at once.
- D? (T19) Find box on the right: the panel takes the full editor height first; the find box (fields, then list) sits over the editor left of the separator. D275 unchanged at the bottom.
- D? (T19) terminal.toggle_position (ctrl+f7) and `/term right|bottom` change only the session; they never show a hidden panel (no shell starts for a layout change). The info notice says where the panel is, notes the bottom fallback when the column is under 60, and when the choice differs from settings.toml names `terminal_position = "..."` (/config). Setting the position it already has says "already ...".
- D? (T19) grow / shrink keep their command names; titles become "Terminal: Increase/Decrease Panel Size" (palette snapshot updated); they change the width while the panel is (or would be shown) on the right at the last frame's size, else the height.
- D? (T19) `/set terminal_position` and `/set terminal_width_percent` apply at once (apply_settings), like terminal_height_percent.
- PTY resize: unchanged mechanism, `terminal::fit` on every frame with the panel's grid; `spawn_size` places a right panel too, so a new terminal starts at the right size.
