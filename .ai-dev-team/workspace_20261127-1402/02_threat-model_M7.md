# Threat model: M7 Git (read, write, Git popup, editor git display)

Task M7-TM. Inputs: `01_proposal_M7_git.md` (approved in full, D297), `01_spec_M7.md` (AC-16..16f),
`02_plan_M7.md`. Nothing in this file is built yet; local git is 2.43.0 (version-dependent items are marked).

Setting: vr-ide is a local, single-user TUI. It runs the `git` CLI (and possibly `gix` for reads) on the
user's own repositories. There is no server and no network listener; the only network traffic is the
user-requested `push` / `pull`. "Attacker" means whoever authored content the user opens:

- **A1, repo content** (likely: any cloned repo): file names, file contents, commit messages, author
  names/emails, branch and tag names, `.gitattributes`, submodule URLs. Arrives through a normal `git clone`.
- **A2, repo-local config** (less likely, high impact): `.git/config`, `.git/hooks`, `core.hooksPath`,
  `include.path` targets. Does NOT arrive through `git clone`, but does through tarballs/zips of a working
  copy, shared folders, container volumes, a repo written by another tool, or a parent directory repo.
- **A3, remote server** (push/pull): `remote:` side-band text, error messages, refs it advertises.
- **A4, the environment vr-ide was started from**: outer `GIT_*` variables (vr-ide launched from a git
  hook, `git rebase -x`, a script), user config with unusual output settings. Not hostile, but it silently
  redirects or reshapes git.
- **A5, concurrency**: the user's own `git` in the terminal panel or another program changing the repo
  between "vr-ide showed it" and "vr-ide acted on it".

## Assets (data/capabilities worth protecting)
| ID | Asset | Why it matters |
|----|-------|----------------|
| AS-1 | Code execution as the user | A repo the user only *opened* must not run programs. |
| AS-2 | Uncommitted work (worktree files, untracked files) | Discard and bad patches can destroy it; it is often not recoverable from git. |
| AS-3 | Index integrity | A wrong `git apply --cached` stages content the user never saw, then gets committed. |
| AS-4 | Commit history and remote | Wrong commit/amend, unintended push, push to the wrong repo. |
| AS-5 | Credentials (tokens, ssh/gpg passphrases, URLs with userinfo) | Must stay inside git's helpers / ssh-agent / gpg-agent; never typed into or shown by vr-ide. |
| AS-6 | The host terminal | Escape sequences in git output can rewrite the screen, set the clipboard (OSC 52), change the title, spoof a diff. |
| AS-7 | UI responsiveness (AC-1, AC-16e) | Huge repos/outputs or hung git must not freeze the editor or leak processes. |
| AS-8 | Which repo is acted on | Multi-root, nested repos, parent repos (e.g. `$HOME` dotfiles repo), env-redirected repos. |

## Trust boundaries & data flows
| ID | Flow | Boundary crossed |
|----|------|------------------|
| F1 | Automatic reads (status, diff, blame, log, branch, ahead/behind) on open/edit/fs events | repo files + repo config → git/gix process → vr-ide parser |
| F2 | User-initiated reads (`/git log`, `/git show <sha>`, `/git blame`, Rescan) | user-typed arguments → git argv |
| F3 | Stage / unstage file (`git add`, `git restore --staged`) | UI selection → path argv → index |
| F4 | Stage / unstage hunk or lines (`git apply --cached [-R]`, patch generated by vr-ide) | displayed diff → generated patch (stdin) → index |
| F5 | Discard file / hunk (+ recovery copy) | UI selection → worktree overwrite/delete; copy → `state_dir()` |
| F6 | Commit (message, amend, sign-off) | message box → git stdin; hooks / gpg run by git |
| F7 | Push / pull in the background | git → ssh/https → remote (A3); credentials via helpers |
| F8 | Rendering of every git-derived string in the popup, gutter, status bar, inline blame | repo/remote text → ratatui buffer → host terminal |
| F9 | Process environment and spawning | vr-ide env (A4) → git child; child ↔ controlling TTY |

## Security requirements for implementation
Every test runs real `git` in a temp repo with a hermetic environment (`HOME`, `XDG_CONFIG_HOME` and
`GIT_CONFIG_GLOBAL` pointing into the temp dir, `GIT_CONFIG_NOSYSTEM=1`) so the developer's own config
cannot hide or cause a failure. "Marker" = a script that creates a file when run; the test asserts the file
never exists.

### M7-1 — read library, process runner (all later git calls reuse it)
- **SEC-1 (process runner)**: one function spawns every git process: no shell; the git binary resolved once to
  an absolute path from `PATH`, skipping relative/empty `PATH` entries; `stdin` null unless vr-ide feeds data;
  the child starts in a new session (`setsid` in `pre_exec`) so it has no controlling terminal; stdout/stderr
  piped; on timeout, cancel, cap (SEC-7) or vr-ide exit the whole process group is killed and reaped.
  Test: a `PATH` shim `git` that opens `/dev/tty` fails to open it; a shim that sleeps is killed at the timeout
  and no child remains (`/proc` scan of the group); a `./git` marker in the repo with `PATH=.:$PATH` is not run.
- **SEC-2 (environment)**: the child env removes every `GIT_*` variable except an allowlist
  (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`, `GIT_SSH`, `GIT_SSH_COMMAND`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`,
  `GIT_CEILING_DIRECTORIES`) and sets `GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, `PAGER=cat`,
  `GIT_EDITOR=true`, `GIT_SEQUENCE_EDITOR=true`, `GIT_MERGE_AUTOEDIT=no`. The repo is always given as
  `current_dir(<workdir>)`, never through env. Test: start the runner with `GIT_DIR`, `GIT_WORK_TREE`,
  `GIT_INDEX_FILE`, `GIT_CONFIG_COUNT=1/KEY_0=core.fsmonitor/VALUE_0=<marker>`, `GIT_TRACE=<file>` pointing at a
  second repo → status/diff report the temp repo, marker and trace file absent.
- **SEC-3 (no program execution on reads)**: reads (automatic and user-initiated) never run a program named by
  repo or global config. CLI reads pass `--no-ext-diff --no-textconv` and
  `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c core.pager=cat -c log.showSignature=false
  -c diff.external= -c protocol.allow=never`, plus an override for every configured
  `filter.<d>.clean|smudge|process` found by `git config --get-regexp` (or, if an empty override is shown
  not to disable a driver on the supported git versions, the read skips worktree conversion for those paths and
  shows them as "modified (filter)"). `GIT_NO_LAZY_FETCH=1` is also set (git >= 2.45; harmless before).
  `gix`, if used, is opened with filter drivers and program-valued config disabled. Test: one marker per key
  (`core.fsmonitor`, `filter.x.clean`, `filter.x.process` with `.gitattributes * filter=x`, `diff.x.textconv`
  with `* diff=x`, `diff.external`, `core.pager`, `log.showSignature`+`gpg.program`, `post-index-change` hook,
  `core.hooksPath`) in local config → run status, unstaged/staged diff, blame, log, show, ahead/behind → no
  marker. A partial clone with a missing blob → read fails fast, no network attempt.
- **SEC-4 (config-independent parsing)**: machine output only: `status --porcelain=v2 -z`
  (`--untracked-files=all` bounded by SEC-7), `diff --no-color --src-prefix=a/ --dst-prefix=b/ --no-relative
  -U3 --full-index`, `log`/`show` with an explicit `--format` using `%x00`/`%x1e` separators and `-z`,
  `blame --porcelain`, plus `-c color.ui=false -c core.quotePath=false -c diff.noprefix=false
  -c diff.mnemonicPrefix=false -c status.relativePaths=false`. Localized human text is never parsed (only shown,
  SEC-15). A message containing the separator byte cannot shift fields (message is the last field).
  Test: a hostile config with every key listed in T4 set in both global and local config → same parsed result
  as with an empty config; a commit message containing `0x1e` and `\n\n` parses into one commit.
- **SEC-5 (argument safety)**: every path goes after `--` with `--literal-pathspecs` (or
  `GIT_LITERAL_PATHSPECS=1`); every revision goes after `--end-of-options` and user-typed revisions are first
  resolved with `rev-parse --verify --end-of-options <x>^{commit}`; SHAs from output are accepted only as
  `^[0-9a-f]{4,64}$`. Paths stay raw bytes (`OsString`/`Vec<u8>` from `-z` output) for operations; the lossy
  UTF-8 form is for display only. Test: files named `-rf`, `--output=x`, `:(glob)*`, `*`, `:!a`, `a\nb`, `a\tb`,
  `"q"`, and a non-UTF-8 name → status lists each exactly once, diff/blame/log target exactly that file, no
  file `x` is created; `/git show --output=x` is rejected with "not a commit".
- **SEC-6 (repo discovery and ownership)**: the repo of a file is found upward from the file's directory; a repo
  owned by another uid, or that git itself refuses (`safe.directory`), shows nothing and no error; vr-ide never
  passes `safe.directory`; discovery does not cross a filesystem boundary; the reported toplevel must be an
  ancestor of the file, otherwise (e.g. `core.worktree` elsewhere) the repo is treated as unsupported.
  Test: a `.git` owned by another uid (or simulated through git's own refusal) above a root → no info; a repo
  with `core.worktree=/tmp/other` → unsupported, no command runs against `/tmp/other`.
- **SEC-7 (resource bounds)**: per-command wall-clock timeout (automatic reads <= 10 s; user reads <= 30 s), a
  byte cap on captured output (e.g. 64 MiB status, 8 MiB per-file diff, log paged by `-n`), at most N concurrent
  git processes per repo (N <= 2) with fs-event debounce and coalescing, a file larger than the cap shown as
  "too large to diff", binary detected and not rendered as text. Test: a 200 MiB text file change → diff
  returns "too large" within the timeout and RSS growth stays under 2x the cap; 1 000 fs events in 1 s → at most
  a few status runs; a sleeping shim → result "timed out", UI thread never waits on it.
- **SEC-8 (lock-friendly reads)**: reads set `GIT_OPTIONAL_LOCKS=0` (`--no-optional-locks`) and never write
  anything under `.git`; the fs watcher ignores `.git/` changes other than `HEAD`, `index`, `refs/`,
  `packed-refs`, `MERGE_HEAD`/`REBASE_*`. Test: after a full read cycle `.git/index` mtime and the `.git` tree
  listing are unchanged; with `.git/index.lock` held by the test, reads still succeed and the lock remains.

### M7-2 — write library
- **SEC-9 (write discipline)**: writes run only on an explicit user action, one at a time per repo (queue);
  each path is re-checked at execution to be inside that repo's workdir (canonical, from SEC-6) and not in
  another root's repo; vr-ide never deletes `index.lock`, never auto-retries a failed write, never runs
  `--force`/`--force-with-lease`, `reset --hard`, `clean`, `checkout .`, `stash drop`, and never passes
  `-c safe.directory`. git's error text is shown verbatim (sanitized, SEC-15). Test: with `index.lock` held,
  stage returns git's error and the lock file is still there; a path from root B submitted to repo A is refused
  before spawning git; grep of the write module for the forbidden flags is empty.
- **SEC-10 (hunk/line patch correctness)**: patches are built from the `-z`/`--full-index` diff of the same path
  (header lines copied from git's own output, not re-quoted by hand), sent on stdin to
  `git apply --cached [-R] --whitespace=nowarn` (never `--unidiff-zero`, `--reject` or `--unsafe-paths`); `--check` runs first; the base blob
  id in the `index <old>..<new>` line must equal the current index (or HEAD for `-R`) blob, else "changed,
  rescan" and nothing is applied. Hunk/line staging is refused (file-level only) for binary, submodule, symlink,
  mode-only, rename/copy, and unmerged entries. "\ No newline at end of file" and CRLF are preserved.
  Test (AC-16f): property test over generated files (CRLF, no-EOL, unicode, empty, tab-indented) and random line
  selections → `git diff --cached` equals the model built by applying the same selection in memory; a failing
  `--check` leaves `.git/index` byte-identical; `apply.whitespace=fix` in config does not change staged bytes.
- **SEC-11 (discard with recovery)**: before any destructive command, the current worktree bytes of the target
  (whole file, or the file before hunk revert) are copied to `state_dir()/git-recovery/<utc>-<repo>-<sanitized
  path>` (dir 0700, files 0600, `fsync`), never inside any repo; if the copy fails nothing is discarded. The
  content hash at confirmation time must equal the hash at execution, else abort ("file changed"). A file with
  unsaved editor changes is refused (or the user is asked separately). Untracked directories: discard only after
  copying every file under a size cap (else refuse); symlinks are copied as links, never followed. Hunk discard
  uses `git apply -R --check` then `git apply -R` on the worktree (no `--cached`). Test: discard file/hunk/
  untracked → recovery file equals pre-discard bytes with mode 0600; unwritable recovery dir → file untouched;
  modify the file between confirm and execute → aborted; symlink to `/etc/passwd` untracked → link removed,
  target untouched, copy is a link.
- **SEC-12 (commit)**: message via stdin `git commit -F -` (plus `--amend`, `--signoff` as fixed argv);
  never `-m <user text>` building, never an editor (`GIT_EDITOR=true`, `-c core.editor=true`); stdin closed after
  the message; empty/whitespace-only message refused in vr-ide before git. Hooks and `commit.gpgSign` run as git
  decides (accepted, T18) under SEC-1 (no TTY, timeout with cancel). Test: message starting with `--amend`,
  containing `#`, NUL-free unicode, 64 KiB → `git log -1 --format=%B` equals it (modulo git's documented
  whitespace cleanup); `core.editor=<marker>` → no marker; amend reuses HEAD's message only when the box is
  unchanged.
- **SEC-13 (push/pull)**: background only, cancellable (kills the process group), inactivity timeout (no
  output for 120 s → kill and report); `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS`/`SSH_ASKPASS` removed,
  `-c core.askPass=`, `SSH_ASKPASS_REQUIRE=never`; if neither `GIT_SSH_COMMAND` nor `core.sshCommand` is set,
  `GIT_SSH_COMMAND="ssh -o BatchMode=yes"`; credentials only via configured credential helpers and ssh-agent;
  vr-ide never asks for or stores a secret. `git push` uses no force flags; `git pull --no-edit`. Output lines
  (incl. `remote:`) pass SEC-15 and URL userinfo (`scheme://user:pass@`) is redacted to `scheme://***@`.
  Test: push to a local `file://` bare repo works; push via a `GIT_SSH_COMMAND` shim that tries `/dev/tty` and
  then waits → fails, no TTY access, killed by cancel; https remote requiring auth (credential helper absent)
  fails at once with git's message; remote hook printing `\x1b]52;c;...\x07` → rendered without ESC; an error
  containing `https://u:tok@h/r` shows `https://***@h/r`.
- **SEC-14 (in-progress states)**: after pull and on every rescan the write library reports `MERGE_HEAD`,
  `REBASE_HEAD`/`rebase-merge`/`rebase-apply`, `CHERRY_PICK_HEAD`, `REVERT_HEAD` and unmerged entries; while
  present, hunk/line staging and discard are refused for unmerged paths, and commit is refused during a rebase
  (the user finishes in the terminal). Test: a conflicting pull fixture → state "merge, 1 conflict", hunk
  stage on the conflicted file refused, index unchanged.

### M7-3 / M7-4 — UI (Git popup, History/Blame, gutter, status bar, inline blame)
- **SEC-15 (display sanitizer)**: every git-derived string (paths, branch/ref names, authors, emails, subjects,
  messages, diff and blame lines, git stderr, `remote:` lines) passes one function before reaching the buffer:
  C0 controls except TAB (expanded), DEL, C1 (U+0080–U+009F), lone CR, and BIDI controls (U+202A–U+202E,
  U+2066–U+2069, U+200E/U+200F, U+061C) become visible placeholders (e.g. `^[` / `<U+202E>`); lines are
  width-truncated; invalid UTF-8 shows U+FFFD. Applies to the popup, inline blame, status bar, gutter tooltips
  and notices. Test: fixture repo with a commit message, author name, branch name, file name and file line
  containing `\x1b[2J`, `\x1b]52;c;ZXZpbA==\x07`, `\x9b31m`, `\r`, `‮` → render every view to ratatui's
  `TestBackend`; no cell symbol contains a char in those classes, placeholders are visible.
- **SEC-16 (destructive confirmations)**: discard asks "Discard changes to <repo>: <path> (<n> hunks)?" with
  Cancel as default (Enter and Esc cancel); the notice after discard names the recovery file path; no
  single-key destructive action without that dialog; push shows the target (`<remote>/<branch>`) in its
  progress line. Test: key-level test `d` then `Enter` → file unchanged; `d`, select Discard, `Enter` → discarded
  and notice contains the recovery path.
- **SEC-17 (repo binding and clarity)**: the popup is bound to one repo snapshot (workdir path + branch shown
  in the header, relative to `$HOME` with `~`) and does not switch when focus moves to another root's file;
  `/git <root-name>` matches only workspace root names; when the repo was found above the workspace root, the
  header says so (e.g. `repo: ~ (parent of root)`). Test: open popup on root A, focus a root B file, stage →
  acts on A; `/git ../x` → "no such root".
- **SEC-18 (stale-view guard)**: every action carries the version (index blob ids / worktree hash) of what was
  shown; if a rescan or fs event changed that item, the action is refused, the view refreshes and a notice says
  so. Test: show a hunk, change the file from outside, press Enter → "changed, rescan", index unchanged.
- **SEC-19 (program-config notice)**: when the repo's local config defines program-running keys (SEC-3 list,
  `core.hooksPath`, executable non-sample hooks), the popup header shows a one-line warning naming them before
  the first write of the session. Test: repo with `filter.x.clean` → warning visible; clean repo → none.
- **SEC-20 (no secret/content leakage)**: vr-ide logs and crash/recovery reports never contain commit messages,
  diff content or URL userinfo; credential-like URL parts are redacted everywhere they are shown (SEC-13).
  Test: run push with a userinfo URL and a failing commit → grep vr-ide's log dir for the token and message → none.

## Accepted risks / open points for the leader
- T18 accepted: user-initiated commit/push run repo hooks and gpg exactly like terminal git (`git gui` does the
  same); SEC-19 makes it visible.
- Parent-repo discovery (T14): showing a `$HOME` dotfiles repo for a root without its own `.git` is a product
  choice. Recommended: show it, labelled (SEC-17), with SEC-7 bounds; alternative: stop discovery at the
  workspace root. Leader/user decides.
- SEC-3 empty-override behaviour of `filter.<d>.process=` on git 2.43 must be proven by the M7-1 test; the
  fallback (skip conversion, label the file) is pre-approved by this model.
