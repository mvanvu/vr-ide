## Design calls
- D? (M7-3) History and Blame are LEFT OUT of the tab bar until M7-4b (not shown disabled): the header shows one tab, `Changes`; `1` selects it, `2`/`3` do nothing yet.
- D? (M7-3) The two file lists are one column for the keys: `up`/`down` run from the last unstaged file into the staged ones and back; `tab` has one stop for the lists (the section the diff shows), then Diff, Message, Amend, Sign off, Commit, Push, Pull, Rescan. With the proposal's literal ring (Unstaged -> Staged -> Diff) tabbing through Staged replaced the unstaged diff, so the unstaged diff could not be reached by `tab` (found by the tests).
- D? (M7-3) Keyboard access to toggles/buttons: they are `tab` stops; `space`/`enter` press, `left`/`right` move between them. No new letter keys beyond the proposal.
- D? (M7-3) Line selection: `shift+up`/`shift+down` (and shift+click / drag) select rows of one hunk; `enter` stages (unstages, in a staged diff) the changed lines of the range; a range over two hunks is refused ("select lines of one hunk"). Without a range `enter` takes the hunk of the diff cursor.
- D? (M7-3) `d` in the file list discards the file; in the diff pane the hunk (or selected lines). Discard on the staged side is refused ("unstage first"). Dialog: "Discard changes to <repo>: <path> (<n> hunks)?" / "Delete the untracked <path> in <repo>?" / "Discard hunk 2 of <repo>: <path>?", buttons Cancel, Discard; Cancel selected (Enter and Esc keep). The notice after: "git: discarded <path>; the earlier content is in <recovery file>".
- D? (M7-3) Push: `p`, the Push button and `/git push` ask "Push <branch> of <repo> to <remote>/<branch>[ and make it the upstream of the branch]?" (Push, Cancel; Push first: push is not destructive and never forced). The progress line is "push → origin/main: <git's last progress line>". While a push or pull runs, `p`, the button (labelled "Cancel push"/"Cancel pull") or the slash command asks "Keep running / Cancel it". Pull starts without a question ("pull ← <upstream>"). `/git push` and `/git pull` show the popup (bound to the active file's repo) so the progress is visible; `esc` hides it and the job goes on; its end is a notice.
- D? (M7-3) Commit: `ctrl+s` in the message box or the Commit button; while a commit (hooks) runs the button is "Cancel commit" (cancels via vr-git's Cancel). Amend on: an EMPTY box (or one still holding a loaded message) gets HEAD's message; a typed draft is never replaced; Amend off with the loaded message untouched gives the draft back. After a commit the box empties and Amend turns off; Sign off stays as set.
- D? (M7-3) Threads: one reader (status, state, head, ahead/behind, write_programs, diffs, discard plans, push target, last message, leftovers) and one writer (index writes, discard, commit, leftover delete/restore) per session, both on `Writer::open`'s runner (D304); push/pull are vr-git Jobs. Queue line: "running: <label> · N waiting". Writes queue behind a push in vr-git's per-repo lock (D303(2)).
- D? (M7-3) SEC-18 for file actions: the writer re-reads status (and the diff when it was shown) and refuses with Stale when the entry or the shown diff differs; hunk/line actions rely on vr-git's own shown-vs-fresh check; discard on the plan's content hash (prepared when `d` is pressed, after the same entry/diff check). A Stale answer rescans; the notice is git's "changed, rescan".
- D? (M7-3) The session lives while hidden (draft, running job, queue); a different repo replaces it only when idle ("a write is still running in <repo>"). A removed root: the session ends after its writes finish (never killed, D304). Exit: commit/push/pull are cancelled, the writer thread gets 3 s, then `Writer::shutdown`.
- D? (M7-3) Saves wait while a discard of the path is queued or running (D305(4)): `save_blocked` guards `save_doc`, `save_as_doc` (target) and Keep mine; the error says "a git discard of this file is running; save again when it is done". Project replace is not guarded (it checks its own file versions; noted as a residual).
- D? (M7-3) Leftover discards (vr-git `leftover_discards`) are offered on every open, one dialog each: `.new` "Keep / Delete", `.old` "Keep / Restore as…" then a name prompt (repo-relative, `..`/absolute refused, never over an existing file: renameat2 NOREPLACE). Both run on the writer thread.
- D? (M7-3) SEC-19 needs to know the repo's program keys: additive read API `Repo::write_programs()` in vr-git (git config --local --includes -z --list, filtered; executable non-.sample hooks of core.hooksPath or common_dir/hooks). Banner: "! this repo's config runs programs on writes: filter.x.clean, hook pre-push" (always shown while true, so it is visible before the first write).
- D? (M7-3) Layout: about 90 % of the screen above the status row when the screen is at least 60x17, else all of it above the status row; lists and diff side by side from 64 inner columns, stacked below (the diff gets 2/3 while it has the keys); message box 4/2/1 rows by height with a `├─ Message ─┤` rule when there is room; hint row from 16 inner rows; an empty status row is given back on small screens.
- D? (M7-3) The app's recovery folder for discards: `Options::recovery_dir = state_dir()/git-recovery` set in `App::load_workspace` only when state_dir is absolute (vr-git refuses a relative one; vr-config's relative fallback then gives vr-git's own default).
