## Design calls
- D? (T24) a: Replace dialog buttons One / All / Cancel, **One is the default**: an in-file replace is one undo step (no file-system write), and Enter, Enter goes on match by match. Title "Replace", message `Replace "<query>" with "<repl>" in <file> (N matches)?`. With no match, Enter only shows "Replace: no results for …" (no dialog). Every answer, Esc included, restores the replace row's edit mode (an open dialog takes edit mode away through `sync_mode`). ctrl+a in the replace field now does nothing (edit.* commands never act behind the box).
- D? (T24) b: `terminal.new` / `terminal.close` are removed from the command registry, not only hidden: no key, palette or slash path is left (D291). A user keymap that still binds them gets the usual "unknown command" startup warning. The buttons call `terminal::new_terminal` / `close_tab`.
- D? (T24) c: '+' starts in the active file's root, else the first root whose folder exists (one stat per click), else the active root (the spawn error is shown). ctrl+` with no terminal uses the same rule.
- D? (T24) d: tab bar: each label ends in "x " (" 1 sh x "); the one 'x' cell closes that tab, the rest of the label activates it; '+' is " + " right after the tabs (after the "+N" marker when tabs are left out); its 3 cells are reserved before the labels are fitted, the hint gives way first. MIN_LABEL 12 → 14 keeps the same title room. The 'x' of a label cut by the bar edge is not clickable. Closing a non-active tab keeps the same terminal active (its index shifts).
- D? (T24) e: the panel hint reads "ctrl+` hide" whether or not the terminal has the keys (the key hides in both cases); "click editor" stays when NUL is passed to the program. A click on the editor (`focus.editor`) leaves a terminal with the panel shown; the zero-row-editor case is unchanged in effect (ctrl+` hides).
- D? (T24) f: live reload: any warning from `Settings::load` / `Keymap::load` / `Keymap::validate` (bad TOML, unknown setting, wrong value, bad key, unknown command, duplicate key) or an unknown theme refuses the whole file: old values kept, one error notice "<file> not applied, old values kept: …". The settings diff is file-before vs file-now (`App.settings_file`), applied on top of the session values, so a `/set`, ctrl+h or grow / shrink of another key stays, and a session `/set` of a key the file did not change stays too. The keymap is replaced whole (a lookup table, no side effects). A removed or renamed-away file is not read (editors do that while saving; values stay). "no setting / key changed" is said only after a save in vr-ide, not for watcher events (the template /config makes would add a notice). The two files are watched as files (`Watcher::watch`, works before they exist when the folder exists); closing their tab or a Save As away does not unwatch them; /config and /keymap watch a folder they just made.
- D? (T24) g: "1 file" in the welcome PROJECT block and the one-root project line; "N+ files" stays plural when the index hit its cap.
