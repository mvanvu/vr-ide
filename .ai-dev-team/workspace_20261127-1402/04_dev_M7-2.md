## API (additive)
- `Writer::open(&Repo) -> Result<Writer>`: own git runner (own process registry and shutdown, review note 3), clones share it; one write at a time per repo across all Writers in the process (`RepoLock` keyed by the canonical git dir, a queue). `repo()` (reads through the writer's runner), `shutdown()` (exit only), `state()`.
- `stage_file(path)` = `git add --all -- <path>` (modified, new, deleted; a folder only when it is a gitlink). `unstage_file(path)` = `git restore --staged --source=<HEAD|empty tree> -- <path> [<rename source>]` (unborn branch and staged renames handled).
- `stage_hunk(&FileDiff, hunk)`, `stage_lines(&FileDiff, hunk, &[line idx])` on a diff from `Repo::diff_unstaged`; `unstage_hunk` / `unstage_lines` on a diff from `Repo::diff_staged`. Line indexes are into `hunk.lines`; context lines are ignored.
- `prepare_discard_file(path) -> DiscardPlan` (tracked: back to the index version; untracked file, symlink or folder: removed), `prepare_discard_hunk(&FileDiff, hunk, Option<&[line idx]>) -> DiscardPlan`; `DiscardPlan{hunks, path(), is_untracked()}`; `discard(&plan, buffer_dirty) -> Discarded{path, recovery: Option<PathBuf>}`.
- `last_message() -> Option<String>`; `commit(message, CommitOptions{amend, signoff}, &Cancel) -> new HEAD oid`.
- `push_target() -> PushTarget{remote, branch, remote_branch, set_upstream}` (Display `origin/main`); `push(target, notify) -> Job`; `pull(notify) -> Job`. `Job{cancel(), canceller(), try_recv() -> Option<JobEvent>, wait()}`, `JobEvent::{Progress(String), Done(Result<JobOutcome{output, state}>)}`. A pull that stops on conflicts is `Ok` with `state` = "merge, 1 conflict".
- `Repo::state() -> RepoState{operation: Option<Operation::{Merge,Rebase,Am,CherryPick,Revert}>, conflicts}` (Display "merge, 1 conflict").
- `Cancel`; `redact_userinfo`, `sanitize_line` (SEC-15 character rules, reusable by M7-3/M7-4; tab expansion and width truncation stay in the UI).
- `Options` += `hook_timeout` (600 s), `network_idle_timeout` (120 s), `recovery_dir` (None = `VR_IDE_STATE_DIR` | `XDG_STATE_HOME/vr-ide` | `~/.local/state/vr-ide`, + `/git-recovery`, read from the runner's env), `recovery_cap` (256 MiB).
- `GitError` += `Cancelled`, `Refused(String)` (policy, text says what to do), `Stale(String)` ("<path> changed, rescan").

## Design decisions (for the leader / reviewer)
- Runner profiles: reads unchanged (SEC-3). Writes (`Index`, `Commit`, `Network`) do NOT blank filter drivers and do NOT force `core.hooksPath=/dev/null`: a user-initiated `git add`/restore/commit/push/pull then behaves exactly like the same command in the terminal (AC-16f; an LFS `clean` filter must run on `add`, `smudge` on restore). This extends accepted T18 / D298(1) from commit+push hooks to filters and `post-index-change` on stage; SEC-19 (M7-4) is the visible warning before the first write. `core.fsmonitor=false`, `protocol.allow=never` + `GIT_ALLOW_PROTOCOL=none` stay on every non-network write. If the leader wants filters blanked on stage, it is one line in `cmd::run_ctl` (but staged content of filtered files would then differ from git's).
- Commit/push/pull drop `--literal-pathspecs` / `GIT_LITERAL_PATHSPECS` (hooks inherit it); they have no pathspec. Index writes keep it.
- `commit -F - --cleanup=whitespace`: `#` lines are kept (the message box is not an editor template), same as `git commit -F file`.
- Hunk/line patches are built for one hunk per call; `Direction::Reverse` keeps git's original header and is applied with `-R` (unstage: `--cached -R`, discard: worktree `-R`). A selection that would put lines after a line without newline is refused (git cannot express it), identically in the in-memory model.
- Hunk/line actions also refused when a `filter` or `working-tree-encoding` attribute applies (the shown diff is not what git compares).
- Push holds the write queue too (simple SEC-9 reading); a stage during a long push waits (M7-3 runs writes off the UI thread). Pull refuses while any operation/conflict is in progress; push refuses during rebase/am; commit refuses during rebase/am and with conflicts, amend refuses during any operation.
- Recovery folder must not be inside any work tree (ancestor with `.git`): a user whose `$HOME` is a dotfiles repo gets "recovery folder ... is inside the git work tree" until `recovery_dir`/`VR_IDE_STATE_DIR` points elsewhere (threat model: "never inside any repo").
- Discard of a tracked file uses `git restore --worktree -- <path>` (no force flag; path re-checked); untracked targets are removed with std::fs after the copy (no `git clean`).
