# T11 Flaky ai_tests::a_focused_session_gives_other_keys_to_the_agent

## Repro
Load loop `$TEAM_WS/qa-artifacts/T11/load.sh <test-bin> <rounds>`: each round runs 6 concurrent copies of `ai_tests`.
Before: `focused-session failures: 5 / 90` (log: qa-artifacts/T11/before.log).
Failing screen (10 s timeout):
```
^N^[[15~^[[17~helVRIDE:0
lo
hello
```

## Root cause (test race, not a product defect)
The test waited for the agent's `CWD:` line, but ECHO_AGENT still runs `env | grep -c` and prints `VRIDE:` before `exec cat`. Keys typed in that window are echoed by the tty immediately, so the agent's `VRIDE:0` line lands in the middle of "hello" and the screen shows `hel` / `lo`. Then `matches("hello").count() >= 2` can never hold. Keys were not lost or delayed: the product passed them through, as the screen shows.

## Fix
`crates/vr-ide/src/ai_tests.rs`, that test only: wait for `VRIDE:` (the agent's last startup line) instead of `CWD:`. The oracle is unchanged: the same key asserts (`app.ran` empty, one session) and the same `hello` x2 check (tty echo plus cat echo). The 10 s deadline is unchanged. Nothing was loosened and no product code changed.

## Evidence
After: `focused-session failures: 0 / 90` (qa-artifacts/T11/after.log); each parallel copy `21 passed; 0 failed` for `ai_tests`.
Guard (profile command, run in .worktrees/T11): `cargo fmt --all --check` printed nothing, exit 0. `run-heavy.sh cargo clippy --workspace --all-targets -- -D warnings` ended with `Finished dev profile ... in 21.96s`, exit 0. (The earlier single-file rustfmt diffs came from different settings than the workspace and are not real.)

## Reuse
StallWatch (search_tests.rs) not needed: the fix is an ordering fix, not a progress-based wait.
