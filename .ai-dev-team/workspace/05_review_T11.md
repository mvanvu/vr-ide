# Review T11 — CHANGES T11

## Findings

[major] README.md (Safety model, 3rd bullet) — conflict-copy rule is wrong (D73)
Quoted: "When a change cannot be applied safely, the other version is kept as a conflict copy named `.vr-ide-conflict-*` next to the file."
Reality (safe_replace.rs header, `keep_conflict`, D73): a copy is kept only when an outside write lands during a save's exchange window (the file at the path is no longer our unmodified temp or the expected version); the same applies to project replace in vr-search. An ordinary "file changed on disk" refusal keeps no copy.
Fix: "If another program writes the file in the instant a save (or a project replace) is swapping it in, vr-ide puts the other version back or keeps it as `.vr-ide-conflict-*` next to the file, and the error names where it was kept. A save that is simply refused because the file changed earlier leaves no copy."

[major] README.md (Safety model, 2nd bullet) — absolute claim contradicted by the code
Quoted: "A concurrent writer's version is never silently replaced or deleted."
Reality: where EXCHANGE is unsupported (non-Linux, some FUSE/network filesystems) the save falls back to check + rename, and a write landing in that gap is replaced (D63 window, safe_replace.rs header). `file.save_overwrite` also replaces on purpose.
Fix: add "on Linux filesystems that support atomic exchange; on others (some network/FUSE filesystems) a write landing in the few microseconds between the final check and the rename can still be replaced".

[minor] docs/keymap.md (Built-in keys, row "Everywhere") — "`esc` dismisses the oldest notice"
In app.rs the notice dismissal runs after the palette, find bar and search panel handlers, so there `esc` closes the panel instead. Fix: "`esc` dismisses the oldest notice (when the palette, find bar or search panel is not focused)".

[minor] docs/keymap.md (Project search panel) — omits that `enter` in the replace field requests the replace preview, and `enter` on the results confirms the preview when one is shown (search.rs:859-863). Fix: "`enter` searches (query field), previews the replace (replace field), opens the result, or confirms a shown preview".
