## New states (round 0)
State added: a worker thread per highlighted document, published snapshots (versioned), pending-edit list, per-layer cached trees and root injection records.
| Case | Behaviour | Test |
|---|---|---|
| quit / close document (drop) | drop sets the cancel flag and closes the channel; an in-flight parse stops at its next progress check; drop never joins (no wait on the UI thread); the thread ends | dropping_the_highlighter_stops_its_worker (notifier refcount back to 1 within 10 s; drop < 50 ms) |
| cancel / Esc | n-a: no user-cancellable operation (highlighting has no UI action) | — |
| error halfway | root parse timeout → `Disabled::Timeout` (plain, notice), worker ends; embedded block timeout/failure → that block keeps host colours; query compile error → `Disabled::Query`; worker panic → caught, `Disabled::WorkerFailed`; edits after the worker ended → no-op, status stays disabled | parse_timeout_stays_plain_and_reports, edits_after_a_timeout_stay_plain_and_reset_tries_again |
| input changing (edits while parsing) | queued, coalesced into one reparse; spans of the older snapshot are shifted through pending edits, edited bytes plain, never shown for other text | edit_during_the_initial_parse_never_returns_stale_spans, edits_after_a_parse_shift_old_spans_until_the_reparse_lands, incremental_reparse_equals_full_reparse_on_random_edits |
| second request (reset/reload while parsing) | old worker cancelled, new shared state + worker; old worker cannot publish into the new state | reset_never_shows_spans_of_the_old_text |
| concurrent writer | n-a: no file I/O; the worker reads immutable rope snapshots (Rope clones), never the buffer | — |
| call that never returns | no I/O in the engine; parse bounded by parse_timeout + cancel flag; `spans()` bounded by query_timeout; `wait()` bounded by its timeout; the UI thread never takes a lock held during parsing (the mutex is held only to swap/clone an Arc) | parse_timeout_stays_plain_and_reports, spans_call_is_bounded_by_the_query_timeout, worker_never_blocks_the_caller_on_a_5mb_file |
| text grows past max_highlight_bytes while editing | disabled (`TooLarge`), worker stopped, plain until reset | files_over_max_highlight_bytes_are_disabled |
No case can lose user data (the engine never writes text or files).

## Deviations
- No tree-sitter-highlight in the engine (D? above); "HighlightConfiguration" is vr-syntax's own `LanguageConfig`. Locals queries unused.
- Initial parse is never on the caller's thread (no small-file sync path); `wait(timeout)` lets M4-3 wait a bounded few ms for small files if it wants first-frame colours.
- Edit points use ropey's line index (cr_lines: a lone CR counts as a line break, tree-sitter counts only LF); only node row/column reporting is affected — the engine works in bytes only.
- Multi-MB edit-to-colour latency is tree-sitter-bound (numbers above), not "next frame".
- Embedded layers paint over their host without clearing it; nested (non-root) layers still run their injection query over the whole layer each cycle (a large PHP file's combined HTML layer pays it; the 200 KB numbers include such a case for HTML only).
