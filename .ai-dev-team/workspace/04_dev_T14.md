## Gate (one place)

Searched: `grep -rn "editable_doc|active_doc_mut|docs\[|docs.get_mut"` — the remaining `active_doc_mut` users only move the selection (find select, search open_match, nav.goto_line, mouse click/drag, select_all, move_with, page); `docs[ti]` in search.rs:1198 is project replace (allowed, D145 (6)); `doc.reload()` in app.rs recheck / file.rs is the external reload (allowed). The mouse has no paste / middle-click / drag-move path (route_mouse: click, drag-select, wheel, tab click only).

## New states (round 0)
State: `View.edit` per tab, `App.editor_seen` (tab that had the editor keys at the last sync), the cursor-shape cache in `event_loop::run`. No thread, job, I/O or kept text.
- Tab switch / open / close: `sync_mode` sees a new tab -> every tab read (untitled: edit). `close_doc` shifts `editor_seen` with the indices; closing the edited tab forgets it, the next tab is read (test closing_the_edited_tab_…).
- Explorer, search panel, dialogs: leaving resets; returning is read (tests back_from_the_explorer…, save_as_and_the_external_change_prompt…).
- Palette: keeps the mode while open; a picked command runs in it; Esc / click outside -> read (palette_esc…, edit_mode_runs_from_the_palette, dialog_tests::palette_enter_runs_command).
- Find bar: keeps the mode; Esc closes the bar; ctrl+i works from it; replace refused in read (find_works…, esc_in_the_find_bar…).
- Reload / external change: unmodified buffers reload in read mode (external_reload…); the Reload / Keep mine prompt keeps the user's edits and returns in read mode (save_as_and_the_external_change_prompt…). Project replace writes open buffers regardless of mode (project_replace_preview_and_confirm).
- Save As: the buffer is written from read mode; back from the prompt in read mode (same test).
- Recovery: unchanged — recovery writes `docs` whatever the mode (event_loop tests edits_are_published…, loop_error_writes_unsaved_buffers_to_recovery pass).
- Quit: the quit guard still asks for unsaved edits (quit_from_edit_mode…); the user's cursor shape is restored on exit and from the panic hook (pty: CSI 0 SP q seen).
- Cancel / Esc: Esc in edit mode -> read and the selection goes; Esc elsewhere unchanged.
- Error halfway / concurrent writer / a call that never returns: the mode writes nothing and makes no call; a refused edit leaves the buffer untouched (read_mode_blocks…). The cursor-shape write is one escape to stdout like a frame.
- Second request: ctrl+i in edit mode and Esc in read mode are no-ops (Esc in read still dismisses a notice / clears a selection).
Data loss / stuck cases tested: edits survive the external-change prompt and are saved by Save As and ctrl+s from read mode; no state blocks ctrl+i (palette, find bar, explorer all reach edit mode).
