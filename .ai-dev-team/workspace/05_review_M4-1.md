## Findings
[minor] crates/vr-syntax/tests/grammars.rs (blade) — the Blade test never exercises a Blade-only query
Scenario: the sample's `comment`, `tag`, `string` captures all come from the layered HTML query (`<!-- -->`, `<ul>`, `class="users"`). If the vendored `queries/highlights.scm` (directive and bracket captures) were dropped or broken, only `punctuation` would be at risk, and `{{ }}` brackets cover that, but `@tag` on `(directive)` is not distinguished from HTML tags. The parse-without-ERROR assertion does prove the grammar itself.
Fix: assert a capture only Blade can produce, or check that the highlight spans cover a `@foreach` byte range.

[minor] crates/vr-syntax/src/lib.rs `strip_spell_captures` — scans every `@` including those inside string literals and predicate arguments
Scenario: a query line such as `(#eq? @x "@spell")` would have the quoted text removed. No shipped query contains this, and the unit tests cover the captured forms, so there is no reachable defect today.
Fix: skip `"..."` literals while scanning (M4-2 can do this when it touches the function).
