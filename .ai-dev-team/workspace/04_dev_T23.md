## Design calls
- D1 (T23): items and order: New…, Rename…, Copy, Cut, Paste, Delete; each runs the same `explorer.*` command as its key, on the row the right press selected. Labels with "…" open a prompt.
- D2 (T23): the box opens one row under the pointer's row (top-left at the pointer column) so the clicked row stays readable; with no room below it opens just above that row; with no room either way it is clamped to the screen bottom. Clamped left at the right edge. It may cover the status row (keeping the clicked row visible wins).
- D3 (T23): right press on a row that is part of a multi-selection keeps the selection (cursor moves to the row), so Copy/Cut/Delete act on all as their keys do; elsewhere it selects just that row. Below the last row = the root row (cursor 0, selection cleared).
- D4 (T23): dimming follows the commands' own refusals: Rename needs a non-root cursor row; Copy/Cut/Delete need a non-root target (`targets`); Paste needs something copied or cut; New always. Dimmed items are skipped by Up/Down/Home/End, never highlighted by pointer motion, and a click on one does nothing (menu stays open).
- D5 (T23): keys while open: Up/Down/Home/End/Enter/Esc are the menu's; any other key closes the menu and is routed as usual (ctrl+c then copies as always). A held Enter (repeat) never chooses; the menu counts as modal for the Enter settle guard.
- D6 (T23): mouse while open: pointer motion highlights an enabled item; a left press on an item runs it; any press outside closes the menu and is used up (a click in the editor does not move its cursor or focus), except a right press in the explorer, which reopens the menu there. Wheel / releases inside are swallowed.
- D7 (T23): the menu lives in `Explorer.menu`; a dialog opening, hiding the explorer (toggle commands or a frame with the explorer hidden) or the keys leaving the explorer close it.
- D8 (T23): no new key bindings and no new commands (keys are the user's choice); the key column reads the keymap.
- Mouse reporting: `main.rs` already enables `EnableMouseCapture` (1000/1002/1003/1015/1006) for the whole app; the walk confirms `ESC[?1000h` and `ESC[?1006h` at start. A terminal whose program grabbed the mouse: `terminal::handle_mouse` still gets presses in the terminal area before the explorer (unchanged, D211/D218); test `a_right_click_in_a_mouse_program_is_forwarded_not_a_menu` shows the program gets `ESC[<2;3;2M/m` and no menu opens. Only while a menu is open does a press in the terminal area just close the menu (D6).
